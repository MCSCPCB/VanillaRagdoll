# 布娃娃补丁生成器

VanillaRagdoll 的浏览器工具，为第三方 Minecraft 基岩版 Add-on 自动生成独立的布娃娃资源补丁。

网站地址：<https://mcscpcb.github.io/VanillaRagdoll/>

## 使用

1. 选择或拖入 `.zip`、`.mcpack` 或 `.mcaddon`，最大 256 MiB。支持文件夹形式的 BP/RP、嵌套的 MCPACK，以及一个 ZIP 内的多个资源包。
2. 等待自动处理。没有可处理实体时不生成空包；有部分不支持的实体时，保留可处理结果，并列出跳过原因。
3. 点击下载，将补丁导入游戏。启用原资源包，并把补丁放在原包上方。多个独立资源包分别生成补丁，以 ZIP 一起下载，需要解压后分别导入。

补丁名称严格为**原包英文名称 + ` Ragdoll`**，描述为 **`Simple Ragdoll`**，复制原包有效的 PNG 图标。缺少图标时使用本站默认图标。英文名称优先取 `texts/en_US.lang`，其次其他英语语言文件；无法翻译时保留直接名称或使用文件/包文件夹名。

补丁清单有自己的 UUID，并依赖原资源包的 UUID 和版本。生成器不会改写原包清单、模型或贴图，只输出需要覆盖的实体定义、新增计算/布娃娃动画，以及确有需要的独立渲染控制器。相同原包 UUID 对应固定补丁 UUID，补丁版本按生成时刻递增，便于替换先前补丁。

原版实体由 VanillaRagdoll 适配，本工具跳过 `minecraft:` 实体。生成的第三方补丁带有自己的共享计算动画，运行时依赖原资源包；不引用 VanillaRagdoll 的原版专属内核文件。可与 VanillaRagdoll 一起启用。

## 生成策略

- 使用固定版本的 Simple Ragdoll 自动配置与生成核心；源码快照位于 `vendor/simple-ragdoll`，来源提交见 `SOURCE.json`。
- 上传包直接引用原版模型时，使用固定的 1.26.50 原版资源索引解析模型，并复用 `src/physics` 中对应的 VanillaRagdoll 配置。模型数据只参与编译，不写入补丁。上传包自己声明的模型、动画和渲染控制器优先于原版资源，避免覆盖 addon 的自定义资产。
- 原版模型路径同时复用必要的姿态处理：成年／幼年独立配置、默认姿态动画保留、装饰部件姿态冻结、关节初始锚点校准、猫尾连接，以及刌民手臂可见性冻结。刌民使用独立命名的渲染控制器副本，非布娃娃时仍读取原包的可见性条件、材质和贴图。不会把原版实体定义整体套到 addon 上，也不会启用原包未调用的动画。
- 关闭全部行为包 Molang 接口，采用标准物理配置。
- 内置死亡与命名触发：`!q.is_alive||q.is_name_any('ragdoll')`；存活且不再叫 `ragdoll` 时恢复（`q.is_alive&&!q.is_name_any('ragdoll')`）。无需额外开关。继承上一渲染姿态，保留通用死亡侧翻及渲染位置补偿。
- 使用 VanillaRagdoll 已实测的客户端位移采样方案继承初速度，并在死亡初期短暂采样迟到的击退运动。不估计受击骨骼。
- 默认加入摄像机推动：按普通第一人称行走估算玩家碰撞，接触时推醒布娃娃，兼容脱离部件、睡眠及卡墙保护。实现位于 `src/generator/camera-push.mjs`，VanillaRagdoll 的本地构建共用同一模块。没有可靠的全局视角判断，第三人称下接触位置会跟随摄像机；这不是其他玩家之间同步的物理碰撞。
- 活着时采样运动及坐标换算；需要局部姿态的原版模型还会记录上一帧动画通道。物理初始化、世界姿态合成和求解延迟到触发布娃娃；计算动画内部也有条件保护。
- 保留原实体 `scripts.scale` 和正常状态的动画调用。为新增骨骼输出和计算动画加条件保护，避免 UI、正常状态计算。
- 同批结构兼容的实体共用计算动画；每个实体的运行状态和配置独立。编译按批次释放中间结果，计算在 Web Worker 内完成，可终止。

最低游戏版本为基岩版 1.26.50；若原包声明的最低版本更高则保留更高要求。尸体随原实体消失，不延长原版死亡时间。给存活生物命名为 `ragdoll` 可直接进入布娃娃，改为其他名字即可恢复；这只改变客户端模型表现，不停止服务端 AI 和行为。

## 支持范围与边界

面向常规方块模型。自定义模型支持单模型，以及可从渲染控制器明确解析、骨骼名称和层级一致的条件模型切换。已适配的原版模型使用独立配置和姿态采集，可处理骨骼不同的成年／幼年切换；同一实体也可混用自定义模型与原版模型。不猜测动态模型数组和同时叠加的不同模型层。

仅凭模型不能判断实体是否拥有原生运行时渲染行为。末影龙、玩家、凋灵、弹性方块生物、犰狳的特殊模型暂不自动套用对应专用处理；已提供 BP 时也会检查 `runtime_identifier`。普通蜘蛛的特殊死亡旋转只有 BP 明确声明蜘蛛运行时时才启用，不会根据模型名称推测。跳过的实体会列出原因。

循环/缺失父骨骼、绑定表达式、多边形模型、过于复杂的模型、缺少模型、引用有歧义的重复资源、已有布娃娃以及无法安全生成的实体会跳过。已提供 BP 时可排除无生命值及部分特殊原生渲染实体；仅提供 RP 无法得知其服务器行为。

检查保证的是生成结构、引用、Molang 语法及可检查的模型条件，不能模拟 Bedrock 的完整渲染器，也不能保证任意第三方包的运行效果。原包原有错误不由补丁修复；特殊死亡逻辑、原生渲染行为及其他叠加资源包仍需游戏实测。不要将“生成成功”理解成所有 addon 已经过游戏兼容认证。

文件不上传到服务器，也不存入浏览器持久存储。GitHub Pages 只提供静态网站；下载在本地生成。输入路径、嵌套深度、文件数量和声明的展开大小均有检查。生成器不会在 JavaScript 中执行上传的 Molang。

界面支持中文和英文。首次访问按浏览器语言选择，顶栏的语言按钮可切换，并在本地记住选择。浏览器只保存语言偏好，不保存资源包。处理中和处理完成后都可以切换语言，进度、错误及跳过原因会随之更新，无需重新生成。

生成器的进度、错误及跳过原因使用 `{ code, params }`，由 `src/i18n.js` 和 `src/messages.js` 翻译。嵌套错误保留 `params.cause`，核心错误保留原始错误键及参数。新增诊断需要同时补充中英文文案，测试按错误代码断言，不依赖中文句子。

## 开发与测试

每个生成的补丁包都有独立的 `animations/sr_patch_web_<包标识>_gate.json`，集中控制该补丁中全部布娃娃的进入和恢复条件。默认保留死亡及命名牌触发。修改门控文件无需重新生成物理代码，详见[门控说明](../docs/ragdoll-gate.md)。页面不提供额外控件。

需要 Node.js 22。进入本目录运行：

```sh
npm ci
npm run dev
```

发布前检查：

```sh
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

单元/集成测试覆盖归档边界、原包不变、名称及清单、跳过处理、生成引用、双语诊断和实际编译后的死亡/击退脚本。测试用 Molang 执行器只执行受控的生成样例，不包含在网页中。浏览器测试使用正式构建并挂在 `/VanillaRagdoll/` 子路径，检查 Worker、下载、取消、重试、语言选择及记忆、已有结果和错误切换、两种语言在 1280/800/440px 下的布局，以及无外部上传请求。默认测试语言为中文，英文自动选择单独验证。截图保存在忽略的 `test-results/`。

第三方实际 addon 包只用于本地回归，不纳入本仓库。更新核心时从明确的 Simple Ragdoll 提交复制 `SOURCE.json` 中列出的文件，保持相对路径，更新来源记录，再执行以上检查。勿让网站构建依赖开发者机器上的相邻目录。

原版适配快照位于 `src/generator/vanilla/`，`SOURCE.json` 记录每份物理配置和适配脚本的来源哈希。维护者在具有项目原版基线及本地构建工具的工作区运行 `node website/scripts/sync-vanilla.mjs` 更新；普通构建和 GitHub Actions 直接使用提交的快照，不依赖本机游戏文件。更新后必须重新执行原版模型、姿态、正常行为和浏览器测试。该快照继续以 1.26.50 为基线，未混入 26.60 的猫、羊定义改动。

## 部署

仓库 Settings → Pages → Source 选择 **GitHub Actions**。工作流在根目录 `.github/workflows/website.yml`：

- `main` 的网站相关修改和手动触发：安装依赖、生成/执行测试、构建、浏览器测试、发布 Pages。
- Pull Request：只构建和测试，不部署。
- 部署产物仅为 `website/dist/`；不上传项目的 `src/` 资源包或本地测试素材。
